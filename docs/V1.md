# v1 API — Fluent Wrapper over the Official Claude Agent SDK

> **Status: alpha** (`1.0.0-alpha.0`). The v1 API lives at the `./v1` subpath and
> is separate from the classic API until it becomes the default at `1.0.0`.
> Method names may still shift; feedback welcome on the issue tracker.

The v1 API keeps this package's fluent `claude()` builder and `ResponseParser`
ergonomics, but runs every query through the official
[`@anthropic-ai/claude-agent-sdk`](https://www.npmjs.com/package/@anthropic-ai/claude-agent-sdk)
instead of this package's own subprocess transport. That means:

- **The official SDK owns the wire protocol.** It is versioned 1:1 with the
  Claude Code CLI, so message parsing can never drift the way a hand-rolled
  wrapper can.
- **The CLI is bundled.** The official SDK ships the `claude` binary as a native
  dependency — no separate `npm install -g @anthropic-ai/claude-code` step.
- **Capabilities a spawn-per-query wrapper can't have** become available:
  in-process MCP tools, lifecycle hooks, permission callbacks, real token
  streaming, and persistent bidirectional sessions with mid-run controls.

```ts
import { claude } from '@instantlyeasy/claude-code-sdk-ts/v1';

const text = await claude()
  .withModel('sonnet')
  .allowTools('Read', 'Grep')
  .query('Summarize the README')
  .asText();
```

`query()` returns the same `ResponseParser` as the classic API, so `asText()`,
`asResult()`, `asJSON()`, `getUsage()`, `asToolExecutions()`, `findToolResult()`,
`getSessionId()`, `stream()`, `succeeded()`, `getErrors()`, and `transform()`
all work unchanged — plus the v1-only `asStructured<T>()` (see
[Structured outputs](#structured-outputs)).

## Builder basics

All the familiar knobs, mapped to official SDK options:

```ts
import { claude } from '@instantlyeasy/claude-code-sdk-ts/v1';

const parser = claude()
  .withModel('sonnet')              // model for the session
  .withFallbackModel('haiku')       // automatic fallback
  .allowTools('Read', 'Grep')       // auto-approve list
  .denyTools('WebSearch')           // removed/denied tools
  .acceptEdits()                    // or .withPermissions('plan'), .skipPermissions()
  .inDirectory('/path/to/project')  // cwd
  .addDirectory('/extra/dir')       // additional allowed directories
  .withSystemPrompt('Be terse.')    // appended to the Claude Code preset prompt
  .withMaxTurns(10)                 // cap agentic turns
  .withEnv({ MY_FLAG: '1' })        // extra env (merged over process.env)
  .query('Do the thing');
```

Notes:

- `allowTools()` **with no arguments** enables read-only mode: it denies the
  mutating tools (`Write`, `Edit`, `MultiEdit`, `Bash`, `NotebookEdit`,
  `TodoWrite`) and leaves `Read`/`Grep`/`Glob`/etc. available.
- Tool names are an open type: MCP names (`'mcp__math__add'`) and scoped rule
  patterns (`'Bash(npm run test:*)'`) type-check.
- `withSystemPrompt(text)` maps to
  `{ type: 'preset', preset: 'claude_code', append: text }` — you keep Claude
  Code's default system prompt and append to it. (The official SDK's raw default
  is a *minimal* prompt, which surprises people porting from the CLI.)
- Cancellation: pass an `AbortSignal` via `.withSignal(signal)`.
- `withExecutable(path)` points at a specific `claude` binary; omit it to use
  the official SDK's bundled one.

## Permission callbacks (`canUseTool`)

Decide programmatically whenever a tool call would otherwise prompt. You can
deny with a message, allow as-is, or allow **with rewritten input**:

```ts
import { claude, type CanUseTool } from '@instantlyeasy/claude-code-sdk-ts/v1';

const guard: CanUseTool = async (toolName, input) => {
  if (toolName === 'Bash' && String(input.command).includes('rm -rf')) {
    return { behavior: 'deny', message: 'Destructive commands are not allowed' };
  }
  if (toolName === 'Write') {
    // Rewrite the input: force writes into a sandbox directory
    return { behavior: 'allow', updatedInput: { ...input, file_path: `/sandbox/${input.file_path}` } };
  }
  return { behavior: 'allow' };
};

await claude().canUseTool(guard).query('Clean up the temp files').asText();
```

The callback only fires when the permission flow would fall through to a user
prompt — pre-approved tools (e.g. via `allowTools`) don't invoke it.

## Lifecycle hooks

Register in-process callbacks for the official SDK's hook events. The generic
`addHook(event, callback, { matcher?, timeout? })` covers all 31 events;
conveniences exist for the common four:

```ts
import { claude, type HookCallback } from '@instantlyeasy/claude-code-sdk-ts/v1';

const logToolUse: HookCallback = async (input) => {
  if ('tool_name' in input) console.error('[hook] tool:', input.tool_name);
  return {}; // empty output = no intervention
};

await claude()
  .onPreToolUse(logToolUse, { matcher: 'Bash' })  // only Bash calls
  .onPostToolUse(logToolUse)
  .onUserPromptSubmit(async () => ({}))
  .onStop(async () => ({}))
  .addHook('SessionStart', async () => ({}))       // any other HookEvent
  .query('Run the tests')
  .asText();
```

A `PreToolUse` hook can also block or rewrite a tool call via
`hookSpecificOutput` (see the official SDK docs for per-event output shapes —
the types are re-exported here as `HookInput` / `HookJSONOutput`).

## In-process MCP servers (custom tools)

Define tools as plain functions running **inside your process** — no separate
server binary, no stdio config. This is the headline capability the classic
subprocess wrapper could never offer:

```ts
import { claude, createSdkMcpServer, tool } from '@instantlyeasy/claude-code-sdk-ts/v1';
import { z } from 'zod';

const math = createSdkMcpServer({
  name: 'math',
  tools: [
    tool(
      'add',
      'Add two numbers',
      { a: z.number(), b: z.number() },
      async ({ a, b }) => ({ content: [{ type: 'text', text: String(a + b) }] })
    )
  ]
});

const answer = await claude()
  .withMCPServer(math)
  .allowTools('mcp__math__add')
  .query('What is 21 + 21? Use the add tool.')
  .asText();
```

Tool input schemas are Zod shapes (Zod 3 and 4 both work); handlers receive
typed, validated arguments.

## External MCP servers

stdio / SSE / HTTP servers pass through with the official config shapes:

```ts
claude().withMCP({
  filesystem: { type: 'stdio', command: 'npx', args: ['-y', '@modelcontextprotocol/server-filesystem', '/data'] },
  internal:   { type: 'http', url: 'https://mcp.example.com', headers: { Authorization: 'Bearer …' } }
});
// or one at a time (config must carry a name):
claude().withMCPServer({ type: 'stdio', name: 'filesystem', command: 'npx', args: ['…'] });
```

## Sessions: resume, fork, and inspect

```ts
import {
  claude, listSessions, getSessionInfo, getSessionMessages,
  forkSession, renameSession, deleteSession
} from '@instantlyeasy/claude-code-sdk-ts/v1';

// First query — capture the session id from its own parser
const first = claude().query('Pick a number between 1 and 100');
await first.asText();
const sessionId = await first.getSessionId();

// Resume it later (same conversation state)
const recall = await claude().resume(sessionId!).query('What number did you pick?').asText();

// Or resume into a *fork* (leaves the original untouched)
await claude().resume(sessionId!).forkSession().query('Try a different approach').asText();

// Inspect stored sessions
const sessions = await listSessions({ limit: 10 });
const info = await getSessionInfo(sessionId!);
const messages = await getSessionMessages(sessionId!);
await renameSession(sessionId!, 'number-guessing experiment');
await deleteSession(sessionId!);
```

## Structured outputs

Ask for the final result as JSON matching a schema, and read it typed:

```ts
const result = await claude()
  .withOutputFormat({
    type: 'object',
    properties: {
      language: { type: 'string' },
      loc: { type: 'number' },
      hasTests: { type: 'boolean' }
    },
    required: ['language', 'loc', 'hasTests']
  })
  .query('Analyze this repository')
  .asStructured<{ language: string; loc: number; hasTests: boolean }>();

if (result) console.log(`${result.language}, ${result.loc} LOC, tests: ${result.hasTests}`);
```

`asStructured()` returns `null` when no structured output is present. The plain
text result remains available via `asResult()` on the same parser.

## Real token streaming

`streamText()` yields the model's **actual incremental tokens**, backed by the
official SDK's `stream_event` deltas — unlike the classic API's token stream,
which re-chunked already-complete messages:

```ts
for await (const token of claude().withModel('sonnet').streamText('Write a haiku about rivers')) {
  process.stdout.write(token);
}
```

Lower-level access: `runV1QueryRaw(prompt, options)` yields the unadapted
official message stream (including non-text `stream_event`s), and
`streamTextDeltas(prompt, options)` is the function `streamText()` wraps.

## Bidirectional sessions and mid-run controls

`session()` keeps the agent process alive: send multiple messages, iterate the
live stream, and steer mid-run — interrupt, switch model, change permission
mode. None of this is possible with one-shot spawning:

```ts
const s = claude().withModel('sonnet').acceptEdits().session('Start refactoring the auth module');

// Consume the live stream (same Message shapes as the classic API)
const consumer = (async () => {
  for await (const msg of s) {
    if (msg.type === 'assistant' && Array.isArray(msg.content)) {
      for (const block of msg.content) {
        if (block.type === 'text') process.stdout.write(block.text);
      }
    }
    if (msg.type === 'result') break; // a turn completed
  }
})();

s.send('Also add tests for the changes');   // queue a follow-up turn
await s.setModel('opus');                    // upgrade the model mid-session
await s.setPermissionMode('acceptEdits');    // change permissions mid-session
// await s.interrupt();                      // stop the current turn if needed

await consumer;
await s.close();                             // end input + tear down the process
```

`s.controls` exposes the raw official `Query` object for everything else it
supports (MCP status, context usage, supported models, …).

## Migrating from the classic API

The classic API (`import { claude } from '@instantlyeasy/claude-code-sdk-ts'`)
keeps working. To move a call site to v1, change the import and check this table:

| Classic (`.`) | v1 (`./v1`) |
| --- | --- |
| `claude().query(p)` → `ResponseParser` | same |
| CLI must be installed separately | CLI **bundled** by the official SDK (`withExecutable()` to override) |
| `.withModel / .allowTools / .denyTools / .inDirectory / .withEnv / .addDirectory / .withSessionId / .withSignal / .withLogger / .onMessage / .queryRaw` | same names, same behavior |
| `.withPermissions / .acceptEdits / .skipPermissions` | same, and modes actually cover `plan` / `auto` / `dontAsk` too |
| `.withMCP([{ name, command, args }])` (array) | `.withMCP({ name: { type: 'stdio', command, args } })` (name-keyed map) or `.withMCPServer(server)` |
| `.withTimeout(ms)` | not yet in v1 — use `.withSignal(AbortSignal.timeout(ms))` |
| `.debug(true)` | not in v1 — set a `stderr` callback via official options (planned) |
| `.withConfigFile / .withRolesFile / .withRole` | not in v1 — compose builder calls directly, or keep those call sites on the classic API |
| `.onAssistant / .onToolUse` | use `.onMessage()` and check `msg.type`, or hooks (`onPreToolUse`) |
| `systemPrompt` option (appended) | `.withSystemPrompt(text)` — appends to the Claude Code preset |
| — (not possible) | `.canUseTool()`, hooks, `.withMCPServer()` (in-process), `.withOutputFormat()` / `.asStructured()`, `.streamText()`, `.session()`, `.resume()` / `.forkSession()`, session utilities |

Auth is unchanged: the CLI owns it (`claude login`, `ANTHROPIC_API_KEY`,
Bedrock/Vertex env vars). There is still no `apiKey` option.

## Current limitations

- **Alpha.** API may change before `1.0.0`; pin exact versions.
- The official SDK is currently a dependency of the whole package, so classic-only
  users also install it. Before `1.0.0` this will be restructured (likely a
  `./legacy` split) so each API pays only for what it uses.
- The adapter surfaces `assistant` / `user` / `system` / `result` messages;
  richer variants (thinking blocks as first-class, `task_*`, non-text
  `stream_event`s) are only available via `runV1QueryRaw()` / `s.controls` for now.
- No `withTimeout()` / `debug()` builder methods yet (see the migration table
  for workarounds).

Progress and the remaining checklist live in [`V1_STATUS.md`](../V1_STATUS.md).
